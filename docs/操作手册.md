## 1. 这套系统是什么

- **系统**：Debian 13（trixie）arm64，XFCE 中文桌面，fcitx5 拼音输入法，Onboard 屏幕键盘。
- **内核**：主线 Linux 6.18.58，加上 `kernel/patches/` 里的补丁和 `kernel/msm8998-xiaomi-chiron.dts` 设备树。
- **启动方式**：手机自带的 bootloader（ABL）从 `boot` 分区加载 Android 格式的 boot.img（内核 + 设备树 + initramfs）。initramfs 找到标签为 `mix2-root` 的 `userdata` 分区，挂载为根目录后切换进 systemd。
- **不依赖 Android**：system、vendor 等分区原样保留但不使用。modem、ADSP 等协处理器的固件取自这台手机自己的 vendor 分区，在构建系统镜像时拷进根文件系统。

所有构建都在 Windows 上完成：内核和根文件系统在 WSL（Debian）里编译，刷机和调试脚本在 Git Bash 或 PowerShell 里运行。

## 2. 准备工作

### 2.1 手机

- 小米 MIX 2（chiron），**bootloader 已解锁**（小米官方解锁工具）。
- 能进入 FASTBOOT：关机状态下同时按住 **电源 + 音量减**。
- 第一次刷机前手机还在跑 Android，而且需要 **root**（用于备份分区和提取固件，见第 3 节）。

### 2.2 电脑（Windows 11）

| 软件 | 用途 |
|---|---|
| WSL2 + 发行版 **Debian** | 编译内核、构建根文件系统 |
| Git for Windows（Git Bash） | 运行刷机、部署、调试脚本 |
| Python 3（Windows 版） | `flash_rootfs.py`、`phone_sh.py` |
| Android platform-tools | `fastboot`、`adb`（放进 PATH，或放在仓库的 `platform-tools/` 目录） |
| 小米 / Google USB 驱动 | 让 Windows 识别 fastboot 设备 |

### 2.3 WSL 里的软件包

在 WSL 的 Debian 里执行：

```bash
sudo apt install build-essential gcc-aarch64-linux-gnu bc bison flex libssl-dev \
    libelf-dev device-tree-compiler cpio kmod python3 mkbootimg mmdebstrap \
    qemu-user-static binfmt-support e2fsprogs xz-utils patch git
```

### 2.4 路径约定（重要）

脚本里写死了下面这些路径。如果你的环境不同，请先全局替换：

| 约定 | 出现在 |
|---|---|
| 仓库放在 **`G:\crazymix2`**，WSL 里对应 `/mnt/g/crazymix2` | 几乎所有脚本 |
| WSL 发行版名叫 **`Debian`** | 文档里的 `wsl.exe -d Debian ...` 命令 |
| WSL 普通用户名是 **`joe`**，内核源码和产物放在 `~/mix2/` | `configure_rootfs.sh`（`KOUT=/home/joe/mix2/out`）、`rebuild_image.sh`（`su joe`） |
| 根文件系统在 WSL 的 `/root/mix2/rootfs` | `build_rootfs.sh`、`configure_rootfs.sh`、`make_image.sh` |

> 小技巧：`wsl.exe` 会把命令行里的 `$` 再展开一次，所以复杂命令最好写进脚本文件，再用 `wsl.exe -d Debian -- bash /mnt/g/crazymix2/scripts/xxx.sh` 执行。Git Bash 里调用 `adb`/`wsl` 时，如果参数里有 Linux 路径，要加 `MSYS_NO_PATHCONV=1`，防止路径被自动改写。

### 2.5 内核源码

```bash
mkdir -p ~/mix2 && cd ~/mix2
wget https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.18.58.tar.xz
tar -xf linux-6.18.58.tar.xz
```

`check_patches.sh` 也会用到这个压缩包（第 11 节）。

## 3. 仓库里没有、需要自己准备的文件

下面这些文件**不进 Git 仓库**：它们有的含个人数据和设备身份信息，有的是高通 / 小米的专有固件，有的太大。

### 3.1 分区备份（强烈建议，刷机前做）

在 Android（已 root）下，通过 adb 备份除 userdata 以外的所有分区：

```bash
adb shell "ls -l /dev/block/bootdevice/by-name/" | awk '{print $8, $10}' > backup/byname.txt
# byname.txt 每行一个“分区名 设备路径”，例如：boot /dev/block/sde40
bash scripts/backup_parts.sh          # 结果在 backup/partitions/
```

> `persist`、`modemst1`、`modemst2`、`fsg` 等分区存有 IMEI 和射频校准数据，丢了无法恢复。请把备份另外存一份到安全的地方，**不要上传到任何地方**。

### 3.2 设备固件包

`configure_rootfs.sh` 从 `backup/firmware/android-firmware.tar` 中提取这台手机自己的固件（modem、ADSP、SLPI、Wi‑Fi、蓝牙、GPU zap shader）。在 Android（root）下打包：

```bash
adb shell su -c "tar -cf /sdcard/android-firmware.tar /vendor/firmware_mnt /vendor/firmware /vendor/bt_firmware /vendor/dsp"
adb pull /sdcard/android-firmware.tar backup/firmware/
```

包内需要有这些路径：`vendor/firmware_mnt/image/`（mba、modem、adsp、slpi_v2、wlanmdsp、bdwlan.bin、modem_pr）、`vendor/firmware/`（a540_zap.*、a540_gpmu.fw2）、`vendor/bt_firmware/image/`（crbtfw21.tlv、crnv21.bin）。

### 3.3 initramfs 用的 busybox

```bash
mkdir -p downloads/busybox && cd downloads/busybox
wget http://deb.debian.org/debian/pool/main/b/busybox/busybox-static_1.37.0-6+b9_arm64.deb
dpkg-deb -x busybox-static_1.37.0-6+b9_arm64.deb x    # make_boot.sh 使用 x/usr/bin/busybox
```

（版本号以 Debian 仓库里实际存在的为准，换版本也可以。）

### 3.4 SSH 密钥

`scripts/mix2ssh` 和 `deploy_kernel.sh` 用 `keys/mix2_ed25519` 登录手机。构建镜像前先生成一对：

```bash
mkdir -p keys && ssh-keygen -t ed25519 -N "" -f keys/mix2_ed25519
```

`configure_rootfs.sh` 会把公钥装进镜像里 `mix2` 用户的 `~/.ssh/authorized_keys`。没有密钥也能用密码登录：`ssh mix2@172.16.42.1`。

### 3.5 本机的 Wi‑Fi / 蓝牙地址

每台手机的出厂 MAC 地址不同，所以不放在仓库的设备树里。复制模板并填入你手机的地址：

```bash
cp kernel/local.dtsi.example kernel/local.dtsi    # kernel/local.dtsi 不会被 git 跟踪
```

- 地址存放在 persist 分区的 `wlan_bt/wlan.mac` 和 `wlan_bt/bt.mac` 里。Android 下也可以在“设置 → 关于手机 → 状态信息”里看到。
- `local-bd-address`（蓝牙）要按**低字节在前**的顺序写；`local-mac-address`（Wi‑Fi）按正常顺序写。模板里有示例。
- `build_kernel.sh` 发现这个文件就会把它接到设备树末尾。没有这个文件的话，蓝牙没有有效地址、无法使用，Wi‑Fi 也拿不到手机自己的 MAC。

## 4. 编译内核

在 WSL 里以**普通用户**执行：

```bash
bash /mnt/g/crazymix2/scripts/build_kernel.sh
bash /mnt/g/crazymix2/scripts/make_boot.sh
```

`build_kernel.sh` 依次做这些事：

1. 按文件名顺序把 `kernel/patches/*.patch` 打到 `~/mix2/linux-6.18.58`。每个补丁打完会在 `.mix2-patches/<补丁名>.applied` 留一个标记，下次跳过；如果你修改了某个已经打过的补丁，要先手动撤销旧的改动并删掉对应标记。
2. 拷入 `kernel/msm8998-xiaomi-chiron.dts`（有 `kernel/local.dtsi` 时把它接在末尾），并加入 dts 的 Makefile。
3. 用 `arm64 defconfig + kernel/chiron.config` 生成配置。片段里没能生效的选项会打印 `NOT APPLIED`。
4. 编译 `Image.gz`、模块和 DTB，结果放进 `~/mix2/out/`。**这个目录每次都会被清空。**

`make_boot.sh` 打包 initramfs（`initramfs/init` + busybox + `tools/mix2-reboot`），生成两个镜像：

| 镜像 | 用途 |
|---|---|
| `images/boot.img` | 正常启动 |
| `images/boot-rescue.img` | 停在 USB 救援 shell（命令行多了 `mix2.rescue`） |

内核命令行固定为：

```
clk_ignore_unused pd_ignore_unused arm-smmu.disable_bypass=0 console=tty0 fbcon=font:TER16x32 quiet loglevel=4 modprobe.blacklist=ipa
```

> **内核大小限制**：解压后的 Image 必须保持在 27 MB 左右。41 MB 的完整 defconfig 内核会和 bootloader 放 ramdisk 的位置重叠，导致无法启动。`chiron.config` 已经裁掉了非高通平台、ACPI、PCI、KVM 等。

## 5. 构建根文件系统和系统镜像

在 WSL 里以 **root** 执行（`wsl.exe -d Debian -u root`）：

```bash
bash /mnt/g/crazymix2/scripts/build_rootfs.sh     # 第一次，或想换基础系统时
bash /mnt/g/crazymix2/scripts/rebuild_image.sh    # 每次改了配置 / 内核之后
```

- `build_rootfs.sh`：用 mmdebstrap + qemu 构建 arm64 的 Debian 13，包括桌面、网络、蓝牙和高通协处理器相关的用户空间。耗时较长，产物在 `/root/mix2/rootfs`。
- `rebuild_image.sh` 依次运行：
  1. `make_boot.sh`（以 `joe` 身份）
  2. `configure_rootfs.sh`：建用户 `mix2`（密码 `mix2`），设置中文 locale、上海时区、自动登录、XFCE 默认配置（来自 `skel/`）；拷入 `overlay/` 里的系统文件；安装打过补丁的 `rmtfs` 和 `qcom-diag`（`packages/`）；启用服务；装入内核、模块和固件
  3. `make_image.sh`：生成 `images/debian13-mix2-rootfs.img.gz` 以及对应的 `.sha256`、`.size`

## 6. 刷机

> ⚠️ 刷机会**清空 userdata 分区**（Android 的数据和内部存储）。请先做完第 3 节的备份。

1. 手机关机，同时按住 **电源 + 音量减**，进入 FASTBOOT，用 USB 线连接电脑。
2. 在 Git Bash 或 PowerShell 里运行：

   ```
   python G:\crazymix2\scripts\flash_rootfs.py
   ```

   提示时输入 `YES` 确认（加 `--yes` 可以跳过）。脚本会：
   - 用 `fastboot boot` 在内存里启动救援镜像（不写任何分区）；
   - 通过 USB 网络（手机 172.16.42.1）把系统镜像用 `dd` 写进 userdata，并校验 sha256；
   - 让手机重启回 FASTBOOT，执行 `fastboot flash boot images/boot.img`，再重启进入 Debian。

> **千万不要用 `fastboot flash userdata` 刷稀疏镜像**：MIX 2 的 bootloader 不会写稀疏镜像里的 FILL 块，文件系统会被悄悄写坏。

第一次开机时，`mix2-growfs.service` 会把根文件系统扩展到整个 userdata 分区（约 52 GB）。

## 7. 日常使用

### 7.1 登录与账户

- 开机自动登录用户 **`mix2`**，默认密码 **`mix2`**。请尽快在终端里用 `passwd` 修改。
- root 账户已锁定，请用 `sudo`。

### 7.2 屏幕、触摸与按键

| 操作 | 效果 |
|---|---|
| 短按电源键 | 熄屏 / 亮屏 |
| 熄屏时摸一下屏幕 | 唤醒 |
| 长按电源键（约 5 秒） | 关机 |
| 音量键 | 调节音量（目前没有声音输出，见第 12 节） |

- **亮度**：顶部面板的电源管理器图标，或“设置 → 电源管理器”。
- **横屏 / 竖屏**：
  - 顶部面板的旋转按钮（循环切换）；
  - 快捷键：`Super+O` 切换横竖屏，`Super+←/→` 横屏，`Super+↑` 竖屏，`Super+↓` 倒置（需要外接键盘）；
  - 命令：`mix2-rotate left|right|normal|inverted|toggle`。
  - 触摸方向会自动跟着旋转，旋转状态在下次登录时恢复。

### 7.3 输入

- **屏幕键盘**：点击输入框时 Onboard 自动弹出，停靠在屏幕底部。
- **中文输入**：fcitx5 拼音，`Ctrl+空格` 切换中英文。
- **蓝牙键盘 / 鼠标**：顶部面板的蓝牙图标里配对即可。

### 7.4 网络

- **Wi‑Fi**：顶部面板的网络图标（NetworkManager），支持 2.4 / 5 GHz、WPA2 / WPA3。
- **USB 连电脑**：手机默认是 USB 设备模式，USB 网卡地址 `172.16.42.1`，电脑会自动获得 `172.16.42.2`。在电脑上执行：

  ```
  ssh mix2@172.16.42.1
  ```

  或者用仓库里的 `scripts/mix2ssh`（使用 `keys/mix2_ed25519`；设置环境变量 `MIX2_HOST=<IP>` 可以改走 Wi‑Fi）。

### 7.5 USB 外接设备（OTG）

- 拔掉连电脑的线，点顶部面板的 **USB 按钮**（或运行 `mix2-usb-mode host`），手机切到主机模式并向外输出 5 V，可以接 Hub、键盘、鼠标、U 盘。
- 再点一次（`mix2-usb-mode device`）切回连电脑的模式。`mix2-usb-mode status` 查看当前状态。
- 如果 Hub 自带外接电源，手机检测到后就不会再输出 5 V。

> 模式切换已经验证过，接 Hub 的实际使用还没有测试。

### 7.6 GPU

- Adreno 540，freedreno 驱动，支持 OpenGL 3.1 / OpenGL ES 3.1。桌面由 glamor 硬件加速。
- 查看：`glxinfo -B`（renderer 应为 `FD540`）。
- 跑分：`sudo apt install glmark2-x11 && glmark2`。
- GPU 频率在 257–596 MHz 之间自动调节（`/sys/class/devfreq/5000000.gpu/`）。为稳定起见，没有启用 670 和 710 MHz 两档。

### 7.7 软件更新

```bash
sudo apt update && sudo apt full-upgrade
```

`rmtfs` 是打过补丁的版本，已经用 `apt-mark hold` 锁定，**请不要解除**，否则 Wi‑Fi 会坏掉。

## 8. 更新内核

### 8.1 先在内存里试一次（不写分区）

```bash
# WSL：编译并打包
bash /mnt/g/crazymix2/scripts/build_kernel.sh
bash /mnt/g/crazymix2/scripts/make_boot.sh
```

如果改了配置并影响到结构体布局，或者改了内建驱动，要先把新模块装到手机上（见 8.2 的 `modules.tar.gz`）。然后让手机进 FASTBOOT，在 Git Bash 里执行：

```bash
fastboot boot images/boot.img
```

只在内存里启动一次，重启后回到 boot 分区里原来的内核。

### 8.2 正式写入

1. WSL 里把产物放到 `images/dev/`：

   ```bash
   cd ~/mix2/out
   cp Image.gz msm8998-xiaomi-chiron.dtb initramfs.cpio.gz /mnt/g/crazymix2/images/dev/
   tar -C modules/lib/modules -czf /mnt/g/crazymix2/images/dev/modules.tar.gz "$(cat kernelrelease)"
   ```

2. Git Bash 里运行 `bash scripts/deploy_kernel.sh`。它会：
   - 把模块装到手机的 `/lib/modules/`；
   - 把内核、设备树、initramfs 拷到 `/boot/mix2/`；
   - 在手机上运行 `mix2-flash-boot`：重新打包 boot.img 写进 boot 分区，**旧的 boot 分区备份在 `/boot/mix2/boot.img.prev`**；
   - 重启并等手机重新连上。

> 内核配置的改动如果影响结构体布局（比如打开 `DETECT_HUNG_TASK`），必须同时更新模块，否则旧模块会崩溃。

## 9. 救援与恢复

### 9.1 新内核起不来

如果手机卡住（黑屏、没有网络）：同时按住 **电源 + 音量减** 约 10 秒，进入 FASTBOOT。boot 分区没有被改过的话，直接 `fastboot reboot` 就会回到原来的内核。

已经写进 boot 分区的新内核如果有问题：

- 先 `fastboot boot images/boot-rescue.img` 进入救援系统，然后在救援 shell 里把 `/boot/mix2/boot.img.prev` 写回 boot 分区；
- 或者直接 `fastboot flash boot <一个可用的 boot.img>`。

### 9.2 救援系统

```bash
fastboot boot images/boot-rescue.img
```

手机会进入内存里的 busybox 环境，并打开 USB 网络：

- `telnet 172.16.42.1`，得到一个交互 shell；
- 或者用 `python scripts/phone_sh.py "命令"` 执行单条命令（端口 5555）。

在里面可以挂载 userdata（`/dev/sda17`）修复文件。如果正常启动时 initramfs 找不到根分区，也会自动进入这个模式。

### 9.3 恢复 Android

刷机前的完整备份在 `backup/`（不在仓库里）：

1. FASTBOOT 下执行 `fastboot flash boot backup/partitions/boot.img`；
2. 进入 recovery，选择清除数据（userdata 现在是 Debian 的 ext4）；
3. 重启，回到原来的 Android。system、vendor 等分区从未改动过。

## 10. 调试方法

### 10.1 常用信息

- 内核日志：`sudo dmesg`；上一次启动的日志：`journalctl -b -1 -k`（journal 是持久化的）。
- **pstore / ramoops 用不上**：主线内核的重启和 panic 走 PSCI 冷复位，内存内容会丢失。
- 硬件信息：`scripts/debug/hwinfo.sh`、`scripts/debug/rmem.sh`（拷到手机上运行）。

### 10.2 自动恢复的启动测试

不需要每次都让人去按键救手机：

1. `scripts/debug/make_dbg_boot.sh "<额外命令行>"` 生成 `images/dev/boot-dbg.img`，命令行里带 `mix2.test panic=5`；
2. `bash scripts/debug/bisect_boot.sh images/dev/boot-dbg.img`：
   - 让手机重启进 FASTBOOT，在内存里启动测试镜像；
   - 测试内核如果起来了，报告 PASS，并把 dmesg 和延迟 probe 的设备存到 `kernel/<名字>.log`；
   - 测试内核如果崩溃，`panic=5` 会让手机重启回 boot 分区里的正常内核，报告 FAIL。

内核卡住而不是崩溃时，加上 `hung_task_panic=1 softlockup_panic=1 hardlockup_panic=1`，把卡住也变成 panic。initramfs 识别 `mix2.crashdump` 参数：如果 USB 控制器一直没出现，它会把 `devices_deferred` 写进日志，然后主动 panic。

### 10.3 显示、触摸、电源相关的小工具

`scripts/debug/` 里的脚本（用 scp 拷到手机的 `/tmp/` 再用 sudo 运行）：

| 脚本 | 作用 |
|---|---|
| `read_disp_regs.py` | 读 DSI 控制器、DPU INTF1、DSI PHY 时序、PLL 分频，并换算出实际时钟和帧率 |
| `dump_pll.py` | 转储 DSI PLL、PHY、lane、DSI 控制器的全部寄存器，用于两种状态对比 |
| `labibb_regs.sh` / `labibb_regs_full.sh` / `labibb_status.sh` | 只读 PMI8998 LAB/IBB 的几个寄存器 |
| `touch_probe.py` | 记录触摸原始坐标（判断触摸偏移） |
| `touch_reset.sh` | 解绑再重新绑定 rmi4，复位触摸芯片 |
| `dpms_cycle.sh` / `dpms_first.sh` | 熄屏再亮屏测试（后者同时记录时钟状态和调试日志） |
| `bl_kick.sh` | 统计 WLED 过压中断频率 |

> ⚠️ **不要一次读完整个 PMIC 的 regmap**（`cat /sys/kernel/debug/regmap/0-0x/registers`），会让手机卡死。要读单个寄存器，用 `dd bs=9 skip=<寄存器地址> count=<个数>`，参考 `labibb_regs.sh`。
>
> PMIC 的寄存器在重启后会保留，实验时改过的值要记得改回去。

### 10.4 核对补丁

```bash
bash /mnt/g/crazymix2/scripts/check_patches.sh
```

把 `kernel/patches/` 打到一份干净的 6.18.58 源码上，和 `~/mix2/linux-6.18.58` 逐个文件比较。直接在源码树里试验修改后，用它确认改动已经同步进了补丁。

## 11. 内核补丁说明

| 补丁 | 作用 |
|---|---|
| 0001 | mmcc：BIMC SMMU 电源域常开，否则显示控制器读不到帧缓冲 |
| 0002 | ath10k：WCN3990 跳过 quiet mode |
| 0003 | 蓝牙 hci_qca：WCN399x 不支持 LE Read Transmit Power |
| 0004 | ath10k snoc：MSM8998 上 DMA 限制为 32 位 |
| 0005–0008 | 来自 porthole 的 PMI8998 电量计驱动 qcom_fg 及修正 |
| 0009–0010 | qcom_smbx 充电驱动：USBIN 读数、Type‑C 电流 |
| 0011 | dwc3：允许用户空间切换 USB 角色（OTG 主机 / 设备） |
| 0012 | JDI NT35596S 面板驱动：时序和 DSI 模式照 bootloader 设置；熄屏时不让面板睡眠，亮屏时重新初始化 |
| 0014 | DPU：MSM8998 没有 CTL_START 中断（porthole） |
| 0015 | a5xx：关闭 flat shading 优化（porthole） |
| 0016 | msm：关闭 GEM 句柄时不拆共享 VM 映射（porthole） |
| 0017 | adreno：给 GPU OPP 表挂上电压调节器，GPU 调频时同时调电压（porthole） |
| 0018 | arm-smmu-qcom：MSM8998 MDSS 使用直通域，开机画面不会被 SMMU 打断 |
| 0019 | LAB/IBB：可选保留 PMIC 默认电压（和原厂行为一致） |
| 0020 | rmi4：作为面板的 follower，面板初始化后复位触摸芯片；熄屏时触摸芯片保持运行 |
| 0021 | DSI 10nm PHY：允许在设备树里指定固定的 D‑PHY 时序（使用 bootloader 的值，否则触摸 X 轴偏移约 160 像素） |
| 0022 | mmcc：补上 MDSS byte_intf 分频器，否则 DSI 字节时钟被拉低一半 |

没有 0013：它是 porthole 的“DSI PHY 10nm VCO 公式”补丁，在这台手机上是错的（会让 PLL 跑到 3.68 GHz、超出规格），已经移到 `kernel/patches-dropped/`，里面有说明。

设备树里和显示相关的关键设置（详见 DTS 里的注释）：

- MDSS 带复位线 `MDSS_BCR`；
- DSI PHY 的 `qcom,phy-timing` / `qcom,phy-clk-pre-post` 使用 bootloader 的值；
- LAB/IBB 使用 `qcom,use-default-voltage`；
- WLED **不开** `qcom,cabc`（开了会持续触发过压保护，导致闪烁）；
- 触摸节点带 `panel = <&panel>`，中断设为电平触发。

## 12. 已知问题与待办

| 项目 | 状态 |
|---|---|
| 声音 | 未适配（耳机 / 麦克风：WCD9335 over SLIMbus；扬声器功放 TAS2559，主线没有驱动） |
| CPU 调频 | 没有 CPRh/OSM 调频，大核停在低频；调度器已改为优先使用小核 |
| 睡眠 / 待机 | 已禁用；不用时请关机 |
| 重力感应、摄像头、指纹、NFC、移动网络 | 未支持 |
| USB 接 Hub | 角色切换已验证，接 Hub 还没有实测 |
| 熄屏耗电 | 熄屏时只关背光，面板保持通电（这样才能可靠唤醒），会多耗一点电 |
| 口袋误唤醒 | 熄屏时触摸芯片保持运行，碰到屏幕就会亮 |
| 无害的日志 | 开机时有 `DSI PLL(0) lock failed`（PHY 上电前的一次预备），WLED 驱动有一条“中断使能不平衡”警告 |
